# Lessons (each one is also a rule in agents/AGENTS.md and a lint)

## 2026-11-11 No single route
Never design a loop, deploy or start path with one host or one credential. Every path has at least two routes, one of which needs no credential a non-coder would have to mint, and a failed host is detected by silence and replaced automatically. Needing a person to create a token or re-authorize a connector is a failure to be recorded (`docs/failures/`), not a blocker to be reported. Lint: `scripts/check_routes.py` in `checks`. Failure record: `docs/failures/2026-11-11-single-route.md`.

## 2026-11-15 Measured is not the same as healthy, running is not the same as working, and working is not the same as converging (from the QNFO fleet)
Read from `https://fleet.qnfo.org/api/managers` at 2026-11-15T18:00Z: portfolio verdict RED, readers 0.14 against a target of 12, cost 442 against 300, 122 of 353 measured metrics in breach, 22820 issue reopens in 7 days, about 190 manager decisions in 24 hours. The fleet is not healthy; what it has is that it knows, hourly, from its own records, and acts on its own verdict. Four rules follow, each one code here. (1) A verdict is computed from records every tick and is never a stored status: `seed/worker/src/ignition.js` `judge`. (2) A loop is proven by the row it leaves each time, and one loop may not take the next one down: `seed/worker/src/pulse.js` `beat`. (3) A loop that returned has not thereby worked: a result of `no-token`, `ok: false` or an error is a failed beat (`pulse.js` `failed`, IDLE-IS-NOT-OK-1); without it a loop with no credential reads as ticking in every slot. (4) Activity is not criticality: 22820 reopens is loops running without closing, and here 560 dispatches in 14 days produced 18 credited deploys (k_eff 0.0679), so the ladder puts `critical` above `looping` and the work is yield per dispatch (`docs/issues/Q-CRIT-DISPATCH-YIELD.json`). The instrument also sits on the clock that beats: the repository-side criticality tick ran on a daily workflow that GitHub did not start on 2026-11-14 and 2026-11-15 (billing) and nothing noticed (`docs/issues/Q-CRIT-ACTIONS-BEATS.json`). Lint: `node --test seed/worker/test/pulse.test.js`.

## 2026-11-28 A queue item must end, a retry must change, and a 200 is not an answer (from Open Questions issues #11, #13, #16)
Three queue issues sat open for days. Causes: every retry read the identical top-6 sources (a retry that changes nothing is a loop, not a retry); both model routes returned HTTP 200 with the body `OK` and the loop quietly fell to a weaker route and then reported the wrong reason ("no base rate"), so a failed route read as a negative finding; nothing capped the attempts, so no item ever got a disposition; and `npm test` never ran `github/*.test.mjs`. Rules: (1) every retried queue item varies its input per attempt and closes with a disposition at a cap (ATTEMPTS-CAP-1); (2) a route reply that is not the expected shape is a failed route and is written into the item's comment (extends IDLE-IS-NOT-OK-1); (3) every directory of tests is named by the `test` script (TEST-COVERAGE-1, `foundation/tenantstd.py`, vendored to every tenant). Fix: ultrastable/open-questions PR 21.

## 2026-11-28 A system merges its own pull requests (AUTOMERGE-1, Rowan)
"An Ultrastable system shall always resolve its own issues and merge its own PRs automatically and timely." The three fix PRs for the stuck queue sat as drafts, one went conflicted when a parallel agent fixed the same loop on main (#20, #31), and no repository had auto-merge (the ruleset gives none), so merging waited for a person. Rule: a pull request the system opened leaves draft and merges once its checks are green and it has no conflict; red or conflicted ones are reported, never merged; one idle an hour after green is a defect. Code: `scaffold/tenant/.github/workflows/automerge.yml.tmpl`, written into every new tenant. Parallel agents fixing one defect collide, so a fix first reads open and merged PRs and main for the same cause.
