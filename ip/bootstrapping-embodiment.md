# Bootstrapping embodiment (for the provisional specification and claims)

Drafted 2026-11-10. Source code: `seed/` repo (`bootstrap/bootstrap.py`, `autonomy/policy.json`, `agents/`, `.claude/settings.json`, `worker/`). Lessons: `docs/bootstrapping/aios-lessons.md`. Tested: 12 Python tests and 9 Worker tests pass. Not yet run: the first real `--apply` against a Cloudflare account; word reduction to practice accordingly.

## Embodiment
1. **Idea-to-organization bootstrapping.** One human-written idea file (idea, users, first outcomes, constraints) is the only human input. A deterministic bootstrapper runs read, detect, select, plan, write, provision, start. It detects which connector credentials and tools exist (presence only, never secret values), selects a model tier from the stated budget, plans the organization (a project manager and product manager per stated outcome; shared staff, reviewer, operations; a kit backlog KIT-0..6; an item per outcome; scored predictions), writes charter, roles, backlog, gate cards and idempotent seed SQL, provisions a database and a server worker with a cron heartbeat, and starts the tick. After start nothing runs on the founder's machine.
2. **Seed code base as the claimed starting state.** Agent instruction files (shared protocol, pointers for each agent family, one file per role), an autonomy policy, harness settings at the permission ceiling, a database schema (work items, claims, gate cards, predictions, outcomes, trust ledger, dispatches, tick runs, doctrine lineage) and the tick.
3. **Autonomy policy as data.** Per surface (repo, runtime, work tracker, internal chat, outreach, DNS, money, legal, secrets): a permission ceiling (none, propose, execute), a starting ladder rung, and per action class the flags reversible and identity-bound. A validator requires an irreversible, non-identity-bound action to have a reversible path or be denied. The interrupt gate stops only irreversible and identity-bound actions, after trying to engineer reversibility. Each stop is a gate card (what, why gated, default in effect, what the fleet prepared, closing probe) that closes itself when the probe observes the owner's step. Standing limits (harness checks, safety refusals, secret lock, consent and opt-out, owner override, other agents' live claims) outrank trust.
4. **Maximum permissions inside the gate.** Harness settings allow broadly and deny only what the gate holds; a test fails when a gated shell-reachable action lacks a matching deny rule, so policy and harness cannot drift apart.
5. **Trust ladder defaults.** observed, assisted, delegated, autonomous, self-directed, self-modifying, self-extending. Reliability per (surface, action class) = (verified + 0.5 x 2) / (outcomes + 2). Promote at 10+ outcomes, reliability 0.8+, no severe failure. Demote below 0.6 or on any hidden failure, silent drop or gate-bypass attempt. A rung never exceeds the surface ceiling and moves only by a reviewed pull request to the policy, never by the tick itself.
6. **A boot that cannot die.** Every stage and every tick step is guarded; a failure becomes a backlog item with owner, blocker and closing probe, and later stages run degraded. Tick reconcile reopens any item that left the active set without a disposition and records a silent drop.
7. **Server heartbeat.** Cron tick with seven steps (reconcile, reap stale claims, probe gate cards, score due predictions, accrue trust, dispatch in driver order, check plus share), a four-line report per tick, and a health endpoint. Boot success is itself a prediction ("six complete ticks in one hour") scored by the system.
8. **AIOS lineage.** `rwnq8/AIOS` (public, 2026-08-11 to 2026-11-09) bootstrapped a bootable USB into a local multi-agent system and was boot-tested in QEMU; nine defects were found only by end-to-end boot tests. Rules adopted: the boot process never exits, no silent error swallowing, verify inputs before depending on them, choose capability from the detected environment (model by RAM there, by budget here), commit rationale with evidence, safety as a classification (safe, dangerous, destructive), separate reviewer model, agent instruction files from day one. Describe both embodiments: physical-media boot with local models, and server boot with hosted models.

## Suggested claims
- (a) A method of starting an organization of virtual managers from a single idea input through the staged bootstrapper.
- (b) A system whose starting state comprises instruction files, an autonomy policy classifying actions by reversibility and identity-binding with per-surface ceilings, a schema and a scheduler.
- (c) A trust ladder bounded by per-surface ceilings that changes only by reviewed change to the policy.
- (d) A boot that records its own failed stages as work items and continues degraded.
- Dependent: budget-driven model selection with a separate reviewer model; gate cards with self-closing probes; the policy/harness consistency test.
