# Where do I see this? (the owner's answer)

**Plain answer.** Two places, both yours alone:

1. **The cockpit** shows Ultrastable's own state in three screens: **Now** (what the loop did), **Next** (what it takes next), **Needs you** (the few acts only you can do, each with its default already in effect). Open it with one command, no accounts:

   ```
   python3 -m foundation cockpit        # writes .selfhost/cockpit/index.html; open that file in any browser
   ```

   It is built from the repository's own records, so it can never disagree with the repo. It also has a step-through run of the system working on itself (`selfhost-run.html`, button "Watch it run").
2. **The live owner dashboard** at `/owner` on ultrastable.io (email-me-a-code login, source `dashboard/`). It keeps the owner task queue, fleet queue, checks, audit log and the daily digest. Recorded as live in `docs/PROJECT-MEMORY.md`.

Everything in both is also in git, so nothing lives only in a screen.

## What the cockpit shows

| Screen | Content | Source in the repo |
|---|---|---|
| Now | counts, last tick as four lines, managers and staff, plussing budget, trust ledger, running loops, gap register, recent merged changes | `foundation/autorun.py`, `seed/worker/src/tick.js`, `instances/ultrastable/gaps.json`, `.github/workflows/`, git log |
| Next | the next twelve items in driver order, parked items with their blockers, funding and outreach status | `docs/issues/`, `outreach/status.json` |
| Needs you | each identity-bound step (why only you, default now, done when), cards the loop opened, outreach cards, where your mail goes | `foundation/data/owner-steps.json`, `outreach/cards/`, `instances/ultrastable/inbox.json` |

Every item links to its record and to the pull request list on GitHub. The cockpit has no write buttons by design: changing state goes through the repository (a PR), so every change is reviewed and recorded. Quick actions for the live queue (Done, Snooze, Hand to fleet) stay in the `/owner` dashboard.

## The demos: the system operating on itself

| Demo | Run | What is real |
|---|---|---|
| Boot and one tick | `python3 -m foundation selfhost` | everything: the records, the real tick, the verifier |
| Ten ticks, with checks and plusses | `python3 -m foundation autorun` (writes `.selfhost/autorun/autorun.html`) | records, tick, checks and trust are real; **staff work is simulated** (no agent is called) and labeled so |
| Public step-through | `demos/public/selfhost-run.html` | the same run with item titles removed; generated by `python3 -m foundation autorun --public --out demos/public` |
| Cockpit | `python3 -m foundation cockpit` | built from the same run plus the records |

The run happens in a scratch database and never edits the repository. After simulated work, each item is checked for real (its closing probe, else its source-of-truth file), by a role other than the doer. An item that fails its check is parked with its blocker and a failed outcome, so trust moves for real reasons. Items marked as yours (`owner:rowan`) open a card with a default and a closing probe, and the loop takes its next item.

## Deploying it later (not done: needs credentials)

`dashboard/cockpit/wrangler.toml` serves the same static output as Workers assets. Build with `python3 -m foundation cockpit --out dashboard/cockpit/dist` and deploy with the Cloudflare credentials (BG-35), behind Cloudflare Access because it shows internal records. The public demo ships with `node deploy/deploy-demos.mjs`. No workflow was added: Actions minutes on private repos are capped.
