# Virtual staff

| Role | Owns | Inputs | Outputs |
|---|---|---|---|
| Portfolio manager | Allocation across projects | Objectives, trust ledger, outcome metrics | Priorities, capacity per project, start/stop decisions |
| Project manager | Delivery of one project | Backlog, dependencies, claims, blockers | Dispatched tasks, unblocked work, status reports |
| Product manager | Roadmap and user value | Feedback, usage, pluses | Ranked roadmap, accepted pluses, acceptance criteria |
| Staff agents | Execution | Assigned task with a stop condition | Verified change, evidence, a proposed plus |
| Reviewer / QA | Independent verification | A claimed result | Pass/fail with evidence; never the same agent that did the work |
| Operations | Running systems | Health signals, incidents | Remediation, failure-mode records |

Rules that make the structure work:

- Every item has an owner, a trigger and a closing check. Nothing leaves the active set without a recorded disposition.
- Managers dispatch; they don't hand work back to people. A step only a person can take (money, legal, credentials) becomes an explicit approval card.
- Roles are configuration, so any organization can map its own structure onto them.
