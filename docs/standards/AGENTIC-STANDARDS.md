# Agentic standards

**Ultrastable is the foundation for any autonomous system.** Ultra-stable: infrastructure that works so nobody notices.

Ultrastable is not an island. It has to talk to agents, tools and services that do not exist yet. So the rule is: adopt the open standard, isolate it behind an adapter, prove it with a test, and re-check it on a date. This file explains the register; the register itself is code (`seed/standards/standards.json`), and `python3 -m foundation standards --check` fails CI when it and the code disagree.

Research date: 2026-11-11. Every entry in the register carries its sources with access dates.

## What the research found (2026-11-11)

1. **The standards have a home.** The Linux Foundation formed the Agentic AI Foundation on 2025-12-09 with MCP (from Anthropic), goose (Block) and AGENTS.md (OpenAI); Cloudflare, Google, Microsoft, AWS, Anthropic and OpenAI are platinum members. A2A (Google, donated 2025) reached v1.0 on 2026-03-12 and joined the same foundation in 2026-08. Betting on these is betting with the industry. ([LF press release](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation); [A2A v1.0 guide](https://josenobile.pages.dev/guides/a2a-protocol/))
2. **MCP is moving to stateless.** The 2026-07-28 revision removes the initialize handshake and session IDs, adds `server/discover`, moves Tasks into an extension, and deprecates Roots, Sampling, Logging, HTTP+SSE and Dynamic Client Registration (replaced by Client ID Metadata Documents), with removal no earlier than 2027-07-28. Our MCP layer negotiates 2026-07-28, 2025-11-25 and 2025-06-18 and holds no session state. ([AAIF migration post](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate); [changelog](https://modelcontextprotocol.net/specification/2026-07-28/changelog)) The changelog page we read is marked as a draft; confirm against modelcontextprotocol.io when the adapter next changes.
3. **Discovery is converging on `/.well-known/`.** A2A agent cards (`/.well-known/agent-card.json`), MCP server cards (SEP-2127, still a proposal), Agent Skills index (`/.well-known/agent-skills/index.json`, draft v0.2.0), API catalog (RFC 9727) and OAuth protected-resource metadata (RFC 9728) are all served. `llms.txt` and `AGENTS.md` cover models and coding agents.
4. **Cloudflare frames the agentic web as readable, discoverable, callable and payable** (2026-08-06): Markdown for Agents, AI Search, WebMCP and Code Mode, x402 wallets and the Monetization Gateway, plus Web Bot Auth for identity. We support what a Worker backend needs today, plan Web Bot Auth and the Agents SDK adapter, and mark payments not applicable because moving money is gated. ([Cloudflare](https://blog.cloudflare.com/the-agentic-internet/))
5. **TOML is how agent clients are configured** (Codex `config.toml` `[mcp_servers]`), JSON for Claude-style `.mcp.json`. We ship both, tested, and keep platform config in what the platform accepts (Wrangler takes TOML or JSONC; ours is JSONC from a template).
6. **Observability has a standard, but it is unstable.** OpenTelemetry GenAI conventions (`execute_tool`, `invoke_agent`, `gen_ai.tool.name`) are all in Development as of v1.42.0 (2026-06-12). We emit them from one adapter file and pin the version, so a rename is a one-file change. ([Dash0 summary](https://www.dash0.com/knowledge/opentelemetry-genai-semantic-conventions-explained))

## Architecture: refactor-proof by construction

```
protocol side (changes with standards)         core (stable)                 platform side (changes with hosting)
acl/mcp.js        MCP framing, versions, auth  core/tools.js   tools as      adapters/d1-store.js   StorePort
acl/discovery.js  llms, cards, OpenAPI, ...    JSON Schema +   functions     adapters/memory.js     second StorePort, registries
acl/a2a (planned) A2A tasks                    core/ports.js   the 4 ports   adapters/bearer-auth.js AuthPort
                                                                             adapters/console-telemetry.js TelemetryPort
```

- **Ports and adapters.** The core knows four ports (store, registries, auth, telemetry). Swapping D1 for another database, Cloudflare for Google Cloud, or JavaScript for another language replaces an adapter and re-runs the port contract test (`ports: store contract d1 and memory`).
- **Anti-corruption layer per external standard.** Every protocol-specific shape lives in one `acl/` file. Unstable standards (anything not `stable` in the register) must name their ACL file or the lint fails.
- **Versioned interface contract.** `seed/worker/contract/mcp-tools.v1.json` freezes tool names and input schemas. Within v1 tools may be added, never removed or narrowed; the test `contract: tools match v1 snapshot` fails otherwise.
- **Every surface is registered.** `seed/standards/surfaces.json` lists each path; the lint fails when `index.js` serves an unregistered path, and the conformance tests fail when a discoverable surface is missing from `llms.txt` or the OpenAPI document.
- **Fail closed.** `tools/call` returns 401 with an RFC 9728 challenge until the owner binds `MCP_TOKEN`; tool listing and discovery are public.

## Connect a client

- Codex: `clients/codex-config.toml`. Claude Code and other MCP clients: `clients/mcp.json`.
- Tools: `ultrastable_tick_status`, `ultrastable_loop_registry`, `ultrastable_glossary_lookup`, `ultrastable_dashboard_state`, `ultrastable_standards_register`.
- The loop registry and glossary tools serve data from the glossary and loop-registry work (`config.registries`, loaded from `doctrine/glossary.json` and `doctrine/loops.json` when those land); until then they report `source: "missing"`. Nothing is duplicated here.

## Keeping it current without a schedule

No scheduled workflow. The register carries `checked` and `stale_after_days` (120); `foundation standards --check` runs on every PR in the existing `checks` job and fails when the research is stale, which forces a re-check on the next change. Planned items are tracked as STD-1 to STD-3 in `docs/issues/`.
